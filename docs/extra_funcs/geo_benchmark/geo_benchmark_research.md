# Розвідка: бенчмарки для H3-based geospatial analytics agent

## 1. Головний висновок

Такі бенчмарки вже існують, причому є декілька доволі близьких до твоєї задачі. Але вони розподілені між різними дослідницькими напрямками. Єдиного усталеного бенчмарку, який комплексно перевіряє AI-агента для аналітики структурованих геоданих із H3-індексацією, сусідством, багаторівневою агрегацією та просторово-часовим аналізом, я в цьому пошуку не знайшов.

На мою думку, тут важливо не шукати лише за запитом `geospatial benchmark`. Він часто приводить до тестів розпізнавання супутникових зображень, геопросторового пошуку або візуалізації карт.

Для твого застосунку правильніше розглядати одразу кілька напрямків:

| Напрямок                            | Що перевіряє                                                                             |
| ----------------------------------- | ---------------------------------------------------------------------------------------- |
| Geospatial Data Analytics Benchmark | Аналітичні операції над структурованими геоданими                                        |
| Spatial Text-to-SQL / Geospatial QA | Чи розуміє агент просторові запити та чи правильно виконує їх над даними                 |
| GIS Agent Benchmark                 | Чи здатний агент планувати й виконувати багатокрокові геоаналітичні сценарії             |
| Spatial Reasoning Benchmark         | Чи розуміє топологію, відстані, напрямки, сусідство, просторові відношення               |
| Spatiotemporal Analytics Benchmark  | Чи вміє аналізувати географічні дані в часовому вимірі                                   |
| H3-specific Benchmark               | Чи правильно працює з ієрархією, сусідством, агрегацією та просторовою дискретизацією H3 |

Останній напрямок особливо важливий: наявні бенчмарки переважно оперують геометріями, GeoJSON, PostGIS, GIS-інструментами або геопросторовими API. Вони не перевіряють безпосередньо H3 як основу табличної аналітики.

## 2. Найцікавіші наявні бенчмарки

Я б виділив сім основних кандидатів, але вони мають різний ступінь відповідності твоїй системі.

### A. GS-QA2 — найближче до аналітики структурованих геоданих



Високий пріоритет

Готовий набір запитань і відповідей



GS-QA2 — Geospatial Question Answering Benchmark

- 3 300 запитань.
- 2 800 запитань стосуються векторних даних.
- 500 додаткових запитань охоплюють растрові дані та їхню взаємодію з векторними.
- Є природномовні запити, SQL-запити та еталонні відповіді.
- Використовуються просторові операції: nearest neighbor, range queries, direction, intersects, агрегування, зональні статистики, ранжування об'єктів.

Цікавий приклад задач: знайти об'єкти в певному просторовому діапазоні, порахувати кількість об'єктів у зоні, визначити найближчі об'єкти, порівняти показники для різних територій.

Чому це важливо: це вже не просто перевірка того, чи агент може показати карту. Тут перевіряється розуміння географічного запиту та отримання правильного аналітичного результату.

Джерела та артефакти:

- [GS-QA2 — GitHub](https://github.com/ZhuochengShang/QARV?utm_source=chatgpt.com)
- [GS-QA2 — Hugging Face](https://huggingface.co/datasets/Zoe/GS-QA2?utm_source=chatgpt.com)

[image](https://www.google.com/s2/favicons?domain=https://huggingface.co\&sz=32)

Datasets at Hugging Face+2

Моя оцінка: один із найкращих вихідних наборів для створення власного тестового сценарію. Я б почав із векторної частини — 2 800 запитань — і адаптував її під H3 та pandas.

Обмеження: це переважно запити до просторових об'єктів, а не складний просторово-статистичний аналіз або повноцінне дослідження часових аномалій.

### B. SpatialQueryQA — перевірка просторових запитів та агрегувань

Високий пріоритет

Цей бенчмарк дуже близький до твоєї концепції роботи з географією як із даними.

Має 90 запитань трьох рівнів складності:

| Рівень       | Кількість | Складність                                     |
| ------------ | --------- | ---------------------------------------------- |
| Basic        | 30        | Прості просторові операції                     |
| Intermediate | 30        | Зв'язані операції, spatial joins               |
| Advanced     | 30        | Багатокрокове просторове міркування, агрегації |

Серед завдань:

- просторове фільтрування;
- пошук найближчих об'єктів;
- відстані та радіуси;
- spatial joins;
- агрегації;
- просторові відношення;
- комбінування кількох операцій в одному запиті.

Посилання: [SpatialQueryQA — GitHub](https://github.com/Autonomous-GIS/Spatial-Text-to-SQL?utm_source=chatgpt.com).

[image](https://www.google.com/s2/favicons?domain=https://github.com\&sz=32)

Autonomous-GIS/Spatial-Text-to-SQL · GitHub+2

Чому це важливо: це хороша основа для перевірки запитів на кшталт:

> Знайди всі комірки, які знаходяться в межах одного сусіднього кільця від заданої зони, об'єднай їхні показники та знайди комірки, де значення перевищує середнє по локальному оточенню.

Сам бенчмарк орієнтований на PostGIS, але логіку завдань можна перенести на pandas + H3.

Недолік — невеликий обсяг. Це радше якісний seed-набір, ніж повноцінна система оцінювання.

### C. GISAgentBench — комплексні завдання для GIS-агентів



Високий пріоритет

End-to-end agent evaluation



Це вже ближче до тестування саме агента, а не окремого SQL-запиту.

GISAgentBench (2026) містить 349 багатокрокових завдань, побудованих на основі реальних практичних запитань із GIS Stack Exchange.

Завдання розбиті на п'ять груп:

| Категорія                                | Кількість |
| ---------------------------------------- | --------- |
| Spatial Joining & Geocoding              | 96        |
| Spatial Overlay & Suitability Analysis   | 93        |
| Terrain Modeling & Hydrological Analysis | 63        |
| Spatial Pattern Analysis                 | 52        |
| Remote Sensing & Image Analysis          | 45        |

Особливо цікаві для нас перша та четверта категорії.

Наприклад, агент повинен визначити кількість об'єктів у заданій відстані від кожної точки, сформувати нову таблицю з результатами або знайти просторові закономірності.

Важливо, що для завдань передбачені виконувані еталонні траєкторії та вихідні файли, з якими можна порівнювати результат. Також аналізуються типові помилки: CRS, неоднозначність меж, топологія геометрій, NoData та невідповідність одиниць виміру.&#x20;

[image](https://www.google.com/s2/favicons?domain=https://arxiv.org\&sz=32)

arxiv.org+3



Посилання: [GISAgentBench — paper](https://arxiv.org/abs/2608.01645?utm_source=chatgpt.com).

Моя оцінка: один із найперспективніших бенчмарків для тестування повного циклу роботи агента: зрозуміти завдання → обрати операції → виконати → отримати вихідний датасет → перевірити результат.

Важливе застереження: у доступному описі автори зазначали, що повний набір даних і траєкторії планували опублікувати. Тому доступність усіх артефактів варто перевірити перед тим, як закладати цей бенчмарк у тестовий конвеєр.

### D. GeoAnalystBench — саме геоаналітика, а не просто GIS-операції

Високий пріоритет

Цей набір цікавий тим, що покриває аналітичні задачі, які часто залишаються поза звичайними GIS-бенчмарками.

Має 50 Python-based завдань, які пройшли експертну перевірку.

Шість основних категорій:

1. Розуміння географічного розташування об'єктів.
2. Розмір, форма та просторовий розподіл.
3. Відносини між територіями та просторові кореляції.
4. Оптимальні місця розташування та маршрути.
5. Виявлення просторових патернів: кластери, тренди, аномалії, неоднорідність.
6. Просторова інтерполяція та прогнозування просторово-часових процесів.

Джерела: [GeoAnalystBench — GitHub](https://github.com/GeoDS/GeoAnalystBench?utm_source=chatgpt.com) та [Наукова публікація](https://doi.org/10.1111/tgis.70000?utm_source=chatgpt.com).

[image](https://www.google.com/s2/favicons?domain=https://onlinelibrary.wiley.com\&sz=32)

Wiley Online Library+3

Чому це важливо: категорії 3, 5 і 6 дуже близькі до реального аналітичного використання твоєї системи.

Особливо цікавими є:

- просторова залежність;
- локальні кластери;
- аномальні області;
- просторова неоднорідність;
- тренди в географічних даних.

Обмеження: оцінювання тут значною мірою базується на відповідності коду та аналітичного workflow. Для нашої задачі бажано доповнювати це перевіркою фактичних результатів на даних.

### E. GeoNatureAgent — дуже цікавий зразок архітектури оцінювання агента



Високий пріоритет

Особливо цікавий метод оцінювання



Це один із найцікавіших результатів пошуку, оскільки він вирішує саме проблему тестування AI-агента, а не тільки якості його геопросторових відповідей.

GeoNatureAgent Benchmark (жовтень 2026):

- 103 завдання.
- 18 категорій завдань.
- Фіксований набір інструментів для агента.
- Доступ до геопросторових екологічних даних через API.
- Детерміноване оцінювання за вісьмома критеріями перевірки.
- Є багатокрокові діалоги, просторове міркування, порівняння регіонів, міжіндикаторний аналіз, часові зміни, обробка помилок.

Джерела: [GeoNatureAgent Benchmark — GitHub](https://github.com/gabrielireland/GeoNatureAgent_Benchmark?utm_source=chatgpt.com) та [Наукова публікація](https://arxiv.org/abs/2610.09112?utm_source=chatgpt.com).

[image](https://www.google.com/s2/favicons?domain=https://github.com\&sz=32)

gabrielireland/GeoNatureAgent_Benchmark · GitHub+3

Ось що я вважаю тут особливо цінним.

Автори розділяють змінну, яку перевіряють, та інфраструктуру, на якій вона працює:

- інструменти агента зафіксовані;
- джерело даних зафіксоване;
- правила оцінювання зафіксовані;
- змінюється сам агент і його здатність правильно обрати інструменти та виконати завдання.

Тобто тестується не лише результат, а й те, чи правильно агент користується доступними можливостями.

Для твого застосунку я б узяв саме цей підхід до архітектури бенчмарку.

Замість прив'язки до екологічних API можна створити фіксований набір H3/pandas-інструментів і перевіряти, наскільки агент здатний самостійно виконати поставлене аналітичне завдання.

## 5. Яких саме бенчмарків поки бракує

Тут, на мою думку, найцікавіша частина дослідження.

Я б не обмежувався адаптацією існуючих GIS-бенчмарків. Потрібен окремий набір тестів, який перевіряє саме концепцію H3 як просторової абстракції для структурованих даних.

Пропоную п'ять функціональних напрямків.

### 5.1. H3 Indexing & Topology

Обов'язкова основа

Перевірка того, чи правильно агент розуміє саму H3-сітку.

Завдання:

- індексація координат на заданому resolution;
- перевірка відповідності точки комірці;
- перехід parent / children;
- визначення 5 або 6 сусідів;
- отримання `grid_disk` та `grid_ring`;
- обчислення відстані в кроках сітки;
- робота з різними resolution;
- поведінка на п'ятикутниках, межах комірок та поблизу антиподальних/антимеридіанних областей.

Тут результати мають бути точними, без LLM-as-a-judge.

### 5.2. Geospatial Tabular Analytics

Основна бізнес-функціональність

Це найближчий напрямок до DataBench та інших табличних бенчмарків.

Завдання:

- додавання H3-індексів до таблиць;
- групування за H3;
- обчислення статистик для комірок;
- об'єднання різних датасетів за просторовим ключем;
- агрегація на різних resolution;
- roll-up від деталізованих комірок до батьківських;
- фільтрація за просторовими характеристиками;
- робота з пропущеними координатами та неповними даними.

Наприклад:

> Є два датасети з різними типами подій. Знайди комірки resolution 8, у яких кількість подій першого типу перевищує середню по їхньому локальному оточенню, та приєднай до них медіанне значення другого показника.

Це вже перевірка аналітичної здатності, а не візуалізації.

### 5.3. Spatial Neighborhood & Pattern Analysis

Дуже важливий напрямок

Саме тут H3 стає особливо корисним.

Завдання:

- локальна статистика сусідніх комірок;
- виявлення кластерів;
- аналіз щільності подій;
- пошук просторових outliers;
- порівняння показників комірки з її сусідами;
- пошук аномальних локальних концентрацій;
- аналіз просторової неоднорідності;
- оцінка просторової автокореляції.

Тут можна використати класичні методи Exploratory Spatial Data Analysis (ESDA):

- Moran's I;
- Local Moran's I;
- Getis-Ord Gi\*;
- spatial clustering;
- density estimation.

Це важливий перехід від простої географічної агрегації до справжньої просторової аналітики.

Окремо треба визначити семантику відстані: `grid_disk(cell, 2)` означає два кроки по H3-сітці, а не обов'язково радіус у кілометрах. Це мають бути різні типи тестових завдань.

### 5.4. Spatiotemporal & Cross-layer Analytics

Стратегічний напрямок

Це, на мою думку, найбільш перспективна частина для розвитку твого застосунку.

Завдання:

- агрегації `H3 × time window`;
- порівняння тієї самої географічної комірки в різні часові періоди;
- виявлення просторово-часових аномалій;
- пошук територій зі зростанням або спадом показників;
- порівняння різних шарів даних;
- пошук зв'язків між просторовими патернами різних типів подій;
- виявлення синхронних змін у сусідніх комірках;
- пошук зон, де кілька незалежних показників демонструють одночасні відхилення.

Наприклад:

> Визнач зони, в яких за останні чотири часові інтервали спостерігається зростання показника A, одночасне зниження показника B та підвищена концентрація подій C у безпосередньому оточенні.

Для такого типу задач наразі не знайшов готового H3-орієнтованого бенчмарку, який би достатньо повно покривав аналітику й агентну поведінку. GeoNatureAgent та DORA дають корисні приклади, але їх потрібно суттєво адаптувати.

### 5.5. Agentic Geospatial Reasoning

Не менш важливо перевіряти не тільки те, чи система здатна виконати одну операцію, а й те, чи агент розуміє, які саме операції необхідно виконати для досягнення результату.

Наприклад, запит:

> Порівняй кількість подій у кожній зоні з її оточенням і знайди зони, що мають нетипово високі показники.

Агент повинен самостійно:

1. Зрозуміти доступну структуру даних.
2. Визначити, які просторові та числові поля потрібні.
3. Зрозуміти, що таке оточення зони.
4. Обрати відповідний H3 resolution та neighborhood.
5. Виконати агрегації.
6. Порівняти локальні показники.
7. Перевірити результат.
8. Пояснити знайдені закономірності.

В окремих завданнях агент повинен також правильно відмовитися від висновку або запросити уточнення, якщо даних недостатньо.

Цей напрямок я б будував за принципом GeoNatureAgent: фіксований набір інструментів і детермінований оцінювач.

## 6. Як я пропоную організувати власний benchmark

Я б не створював один величезний набір довільних запитань. Краще зробити кілька незалежних тестових треків.

## H3 Geospatial Analytics Benchmark

Запропонована структура майбутнього набору

Track 1 — H3 correctness

Індексація, ієрархія, сусідство, кільця, resolution.

Track 2 — Tabular geospatial operations

Pandas, groupby, joins, агрегації, roll-ups.

Track 3 — Spatial neighborhood analytics

Локальні статистики, кластери, outliers, просторові патерни.

Track 4 — Spatiotemporal / cross-layer

Часові зміни, міжшарові зв'язки, просторово-часові аномалії.

Track 5 — Agent workflow

Планування, вибір інструментів, виконання, перевірка та відновлення після помилок.

### Як оцінювати

Я б застосував кілька різних груп метрик.

| Метрика                          | Що оцінює                                         |
| -------------------------------- | ------------------------------------------------- |
| Exact Match                      | Точність дискретних відповідей та ідентифікаторів |
| Numerical Error                  | Точність статистичних обчислень                   |
| Jaccard / Set Precision / Recall | Коректність множин комірок та сусідства           |
| Spatial Join Accuracy            | Правильність об'єднання даних                     |
| Task Success Rate                | Чи отримано правильний кінцевий результат         |
| Tool Selection Accuracy          | Чи правильно обрано функції та інструменти        |
| Execution Validity               | Чи виконується сформований код                    |
| Recovery Rate                    | Чи агент відновлюється після помилок              |
| Explanation Faithfulness         | Чи пояснення відповідає фактичним результатам     |

Ключове правило: для основних тестів істину потрібно отримувати з незалежного reference implementation, а не з відповіді іншої LLM.

Також варто розділити:

- точні операції над H3-індексами;
- наближені географічні операції;
- точні геометричні операції.

Це важливо, оскільки H3-ієрархія не тотожна точному геометричному вкладенню, а кроки `grid_disk` не тотожні фіксованому радіусу в кілометрах.

## 8. Що я рекомендував би взяти в роботу вже зараз

Я б не намагався одразу адаптувати всі знайдені бенчмарки. Найбільш раціональний початковий набір такий:

| Пріоритет | Джерело         | Як використати                                                                     |
| --------- | --------------- | ---------------------------------------------------------------------------------- |
| 1         | GS-QA2          | Взяти векторні запитання для перевірки просторових запитів та табличних агрегацій  |
| 2         | SpatialQueryQA  | Взяти прості, середні та складні сценарії з joins, proximity та aggregation        |
| 3         | GeoAnalystBench | Взяти завдання з просторової неоднорідності, кластеризації та аномалій             |
| 4         | GISAgentBench   | Використати практичні багатокрокові workflow та еталонні результати                |
| 5         | GeoNatureAgent  | Запозичити архітектуру фіксованих інструментів та детермінованого agent evaluation |

Паралельно створити власний H3-specific track для ієрархії, сусідства, локальних статистик і міжшарових операцій.

Мій основний висновок: не потрібно вигадувати весь бенчмарк з нуля. Вже є хороші набори для просторових запитів, GIS workflow та геоаналітичних задач. Але їх потрібно доповнити власним H3-тестуванням, оскільки саме дискретизована гексагональна географія є специфічною особливістю твого агента.

Для подальшого глибокого дослідження я б поставив три головні цілі:

1. Зібрати готові datasets та benchmark tasks, які можна реально запустити, а не тільки процитувати в дослідженні.
2. Визначити спільну таксономію аналітичних можливостей — від базових spatial joins до просторово-часового виявлення аномалій.
3. Сформувати власний H3-native benchmark, який перевірятиме не лише коректність окремих операцій, а й здатність агента самостійно розв'язувати складні аналітичні запити над географічно індексованими таблицями.

Саме третій пункт, на мою думку, може стати найціннішим результатом: він перевірятиме не просто здатність LLM писати GIS-код, а здатність AI-агента використовувати H3 як повноцінну аналітичну модель географії.
